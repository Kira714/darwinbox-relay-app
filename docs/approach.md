# Approach (one page)

**Goal.** Migrate messy multi-file exports into a target system with an agent that decides alone what is safe, and stops for a person only when it is genuinely uncertain — with a UI a non-technical consultant can supervise.

**What runs alone.** Files (Excel sheets/CSV) are parsed with row provenance. Columns are mapped: first by aliases declared in the target schema, then by an LLM (free open-weight models via OpenRouter, user-supplied key) that sees column names and locally computed value *shapes*, not the data. Values are cleaned only in meaning-preserving ways (whitespace, casing, enum spellings, dates that have exactly one valid reading). Rows are reconciled on an identity field, keeping every source row as lineage. Every record is validated against the target JSON Schema *before the first request*, then POSTed with a stable idempotency key.

**Where the line is drawn, and why.** The model only proposes. A mapping is accepted only if the model is confident (default ≥ 85%, adjustable), the column's values actually fit the target field's type/format, the target isn't already taken, and the field exists. Anything else — a competing column, a low-confidence guess, a model outage — becomes a review case that carries the model's suggestion and reasoning. Data-level escalation follows the same rule: `04/05/2024` (two valid dates), two sources disagreeing, a value still invalid after one bounded repair, two people sharing an identity. Each is a case where *business meaning* is missing, not a technical failure. Everything else is done silently but audited. The agent never invents a value, never merges people by name, and never sends a partial batch for a schema problem.

**Escalation.** When blocked, the run shows who it was escalated to and a plain-language list of what is wrong; an optional Slack-compatible webhook notifies them. The consultant approves, corrects or rejects with a required reason; the final decision releases delivery automatically. Delivery failures escalate too: only failed records are retried, and after three consecutive failures the agent stops instead of hammering a broken endpoint.

**Delta beyond the model.** Provenance and an insert-only audit of every change and decision · server-owned reviewer identity, roles (admin/consultant) and revision checks against stale decisions · schema-driven pipeline (bring any flat JSON Schema and HTTP target) · idempotent delivery with receipts, so a lost response never duplicates a write · compare-before-restore rollback that refuses to undo later work · privacy by default (shapes, not values) with encrypted, write-only secrets · deterministic fallbacks so nothing depends on the model being up.

**Honest limits.** Model confidence is self-reported, not calibrated — hence the extra deterministic checks and the adjustable bar. Free models vary run to run (the same files produced 1 or 3 mapping escalations in testing) and are rate-limited. Rollback exists only for the built-in target; an arbitrary HTTP API supports retry. It is a single-process prototype with a mock target.

**Next.** Evaluate thresholds on labelled exports; durable job queue and isolated parsing; reusable client rules with approval; case ownership/SLAs; a real vendor sandbox connector with verified idempotency and undo contracts.
